A two-weekend course · AI systems notes

The machine and the kernel under your GPUs

Four modules on the host side of distributed training and inference.: how the box is wired, what virtual memory does to your bytes, how the kernel schedules the threads that feed the GPU, and how I/O, networks and containers fail. Each module takes ≈35–45 minutes to read, has interactive diagrams you can step through, and ends with a drill you can run on any NVIDIA machine, from an RTX 4090 workstation or a DGX Spark to an 8×H100 node.

DDrills

All drills are in drills/. They need Python 3 with PyTorch (CUDA), nvidia-smi, and optionally sudo apt install hwloc numactl sysstat. Run each one on both machines and keep the output: the pages compare the two.

ModuleCommandWhat it shows
1bash drills/m1_machine.shtopology, NUMA, PCIe links, GPU/NIC affinity; pinned vs pageable bandwidth; big vs small core (or cross-NUMA)
2bash drills/m2_vm.shpage size, THP, CUDA unified-memory attributes; read vs mmap faults, cold vs warm; THP fault counts
3bash drills/m3_cpu.shstrace of a training step; DataLoader COW growth (list vs numpy); launch jitter quiet / noisy / pinned / CUDA graph
4bash drills/m4_io.sh
docker run … sh /d/m4_container_check.sh
bash drills/m4_60s.sh PID		page cache and O_DIRECT; container limits that break training; the 60-second checklist
anybash drills/m5_rack.shcoherence class (ATS, NUMA config, fabric handles), copy engine vs SMs reading CPU memory, NUMA placement
anybash drills/report.shone-page profile of any machine, written to results/<host>.md: headline numbers for comparing machines

Get the drills with git clone https://github.com/kapilsh/ai-systems-notes, or download single files from the links in each module. m5_coherent.cu needs a CUDA toolkit (nvcc).

"x86 + RTX 4090" results were measured on an i9-13900K + RTX 4090 workstation, and "DGX Spark" results on a DGX Spark (DGX OS 7.3.1). The 8×H100 columns are predictions from NVIDIA's documentation, marked as such until measured.
